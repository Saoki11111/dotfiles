# Infrastructure Notes

インフラ、外部サービス、障害時の確認観点をまとめます。

## Cloudflare Pages

- 静的サイト、Next.js、フロントエンド公開候補。
- GitHub連携、build command、環境変数を確認する。
- Preview URLで確認してから本番反映する。
- 独自ドメイン、DNS、SSL設定を確認する。

## GitHub Pages

- 静的サイト公開の候補。
- 無料で使いやすいが、動的処理には向かない。
- build成果物の出力先と公開branchを確認する。

## microCMS

- お知らせ、ブログ、実績などの管理候補。
- APIキーは環境変数で管理する。
- コンテンツ構造を先に整理する。
- 無料枠、API制限、画像容量を確認する。

## 外部API

- 無料枠、課金条件、レート制限を確認する。
- APIキーはコードに直接書かない。
- 障害時の代替表示を用意する。
- 本番利用前に利用規約を確認する。

## 確認観点

- 費用: 無料枠、超過時料金、請求アラート。
- セキュリティ: APIキー、権限、公開範囲、管理者権限。
- 運用: 誰が更新するか、障害時に誰が見るか。
- バックアップ: データの復元方法、エクスポート方法。

## 障害時の確認順

1. 自分のPC、ブラウザ、ネットワークで再現するか確認する。
2. 本番URL、Preview URL、ローカルで差分を確認する。
3. Cloudflare / GitHub / Supabase / microCMS のステータスを確認する。
4. 直近のdeploy、commit、設定変更を確認する。
5. エラーログ、レスポンスコード、ブラウザconsoleを確認する。
6. 影響範囲と暫定対応をまとめる。
