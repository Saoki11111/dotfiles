# Engineering Rules

開発時の基本方針をまとめます。

## 基本方針

- 小さく作る。
- まずローカルで動かす。
- UIの作り込みより、先に動作確認を優先する。
- 複雑な設計や抽象化は、必要になってから追加する。
- 将来的なAWS移行も考慮する。

## Next.js

- まず標準機能で作る。
- App Router / Server Components / API Routes の役割を分ける。
- 状態管理は最小限にする。
- 環境変数は `.env.local` に置き、リポジトリには含めない。
- 本番ビルドで確認する。

## Supabase

- 認証、DB、Storage の責務を分けて考える。
- RLS を前提に設計する。
- SQL変更は、何を変えたか説明できる形で残す。
- 本番データを直接触る前に、影響範囲を確認する。

## JSON管理

- 小規模なデータはJSON管理で始めてもよい。
- データ量、更新頻度、複数人編集が増えたらDB化を検討する。
- スキーマ、必須項目、サンプルデータを残す。
- 手作業更新が増えたら管理画面やCMS化を検討する。

## 確認手順

- `npm run dev` でローカル確認する。
- `npm run lint` があれば実行する。
- `npm run build` があれば実行する。
- 主要画面、フォーム、外部API連携を確認する。

## 将来のAWS移行

- 外部サービス依存をコード内に散らさない。
- APIキー、DB接続、Storage設定は環境変数で管理する。
- 画像、ログ、バックアップの置き場を意識する。
- Cloudflare Pages / GitHub Pages / Supabase から移行できる構成を意識する。
